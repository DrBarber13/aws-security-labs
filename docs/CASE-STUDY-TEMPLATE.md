# AWS Case-Study Documentation Standard

Every case study in this repository contains:

1. a fictional workload, assets, threats, and assumptions;
2. an original architecture or control-flow diagram;
3. identity, network, data, detection, and recovery decisions;
4. an implementation summary written without copied lab directions;
5. positive and negative validation tests;
6. limitations and residual risk;
7. cost-control and cleanup considerations; and
8. security lessons that connect the configuration to risk reduction.

Public artifacts use fictitious account identifiers, resource names, addresses, and events. Access keys, tokens, credential files, state files, account exports, and original coursework remain private.
